## sed 的工作模型

很多人第一次用 sed 时会困惑：为什么 `sed 's/foo/bar/'` 把整行都打印出来了？为什么加了 `-n` 又什么都不输出？这两个问题都指向同一个核心：sed 不是“找到文本、原地改掉”，而是**逐行读入缓冲区、执行脚本、再决定是否输出**。

理解这个循环之后，地址、替换、多行处理和保持空间都会变得可预测。

### 一次循环做四件事

sed 对输入流中的每一条记录执行同一套动作：

1. 读取下一条记录。
2. 把记录放进**模式空间**(pattern space)。
3. 按脚本顺序执行所有匹配的命令。
4. 到达脚本末尾时，默认把模式空间打印到标准输出，然后回到第 1 步。

```mermaid
flowchart LR
  A["读取一条记录"] --> B["放进模式空间"]
  B --> C["按地址执行命令"]
  C --> D["默认打印模式空间"]
  D --> A
```

这条循环有两个重要出口：

- 使用 `-n` 时，第 4 步的默认打印被关闭；只有显式 `p` 才会输出。
- 使用 `d` 时，模式空间被清空并直接开始下一轮，第 4 步不执行。

`q` 会在当前轮打印后退出，`Q` 则连当前轮都不打印。它们属于提前结束，不是常规循环的一部分。

### 模式空间是什么

**模式空间**(pattern space)是 sed 当前正在处理的那一块内存。默认情况下，它只装一条记录，而且**不包含记录末尾的换行符**。

这一点解释了很多现象：

- `s/^/X/` 会在行首加 `X`，因为 `^` 匹配模式空间的开头。
- `s/$/X/` 会在行尾加 `X`，因为 `$` 匹配模式空间的结尾。
- `s/foo/bar/` 只修改模式空间，不会碰磁盘上的文件。
- 默认打印时，sed 会在模式空间后面补一个换行符；所以输出仍然是一行一行。

如果输入的最后一行没有换行符，GNU sed 输出时也不会凭空补一个。可以用字节查看验证：

```shell
printf 'a' | sed 's/a/b/' | od -An -tx1
```

输出只有一个字节 `62`，也就是 `b`，没有 `0a` 换行。

模式空间里的内容可以被命令改写。`s` 改写它，`y` 逐字符替换它，`d` 清空它，`N` 把下一行追加进来。后面的命令看到的是**前面命令修改后的结果**，不是原始输入行。

### 默认打印与 -n

没有 `-n` 时，sed 在每轮结束时自动打印模式空间。所以下面两条命令的输出完全不同：

```shell
printf 'a\nb\n' | sed 's/a/A/'
```

输出：

```shell
A
b
```

```shell
printf 'a\nb\n' | sed -n 's/a/A/'
```

没有任何输出。第二条命令确实执行了替换，但 `-n` 关闭了自动打印，脚本里又没有 `p`，所以结果没有送到终端。

最常见的过滤写法是 `-n` 加 `p`：

```shell
sed -n '2p' examples/data/poem.txt
```

输出：

```shell
violets are blue
```

`p` 是“立即打印当前模式空间”，不是“打印匹配到的片段”。即使地址只匹配一行，`p` 打印的也是整行。

### 命令按顺序执行

sed 脚本可以包含多条命令。它们在同一条记录上按书写顺序执行，后一条看到前一条的结果：

```shell
printf 'cat\n' | sed -e 's/c/b/' -e 's/b/d/'
```

输出：

```shell
dat
```

第一条把 `c` 换成 `b`，得到 `bat`；第二条再把 `b` 换成 `d`，得到 `dat`。如果交换两条命令，结果会不同。

命令可以写成多个 `-e`，也可以写在同一个脚本里用分号分隔：

```shell
printf 'cat\n' | sed 's/c/b/;s/b/d/'
```

分号不是万能的。`a`、`i`、`c` 的文本会一直延伸到行尾，分号会被当成文本内容；这类命令要用 `-e` 或换行分隔。后面的编辑命令章节会专门讲这个坑。

### 地址决定命令作用于哪些行

命令前面可以带**地址**(address)。没有地址时，命令对每一条记录都执行；有地址时，只有匹配的记录才执行。

```shell
sed -n '2p' examples/data/poem.txt
```

`2` 是行号地址，只匹配第 2 行。再看正则地址：

```shell
sed -n '/blue/p' examples/data/poem.txt
```

只打印包含 `blue` 的行。

删除第 2 行：

```shell
sed '2d' examples/data/poem.txt
```

输出：

```shell
roses are red
sed is a stream editor
and so are you
```

注意 `d` 之后没有输出第 2 行，也没有输出一个空行：模式空间被清空，这一轮直接结束。地址的完整形式、范围和否定会在下一篇展开。

### 保持空间是什么

sed 还有一块**保持空间**(hold space)。它不在每轮开始时被重置，可以跨记录保存内容。

默认情况下，保持空间是空的，也不会被自动打印。只有 `h`、`H`、`g`、`G`、`x` 这些命令会读写它。最简单的例子是给每行后面加一个空行：

```shell
sed 'G' examples/data/poem.txt
```

`G` 把换行符和保持空间追加到模式空间末尾。保持空间为空，所以效果是每行后面多一个空行。

保持空间是 sed 处理跨行状态的主要手段，但它也容易把脚本变得难读。日常的字段处理、聚合和排序通常用 awk 更合适；保持空间的典型用途是反转、去重、合并续行这类确实需要跨记录状态的场景。

### 用 --debug 看一轮循环

`--debug` 是 **GNU** 扩展。它把 sed 的内部状态打印出来，非常适合验证你对循环的理解：

```shell
printf 'hello world\n' | sed --debug 's/world/sed/'
```

输出：

```shell
SED PROGRAM:
  s/world/sed/
INPUT:   'STDIN' line 1
PATTERN: hello world
COMMAND: s/world/sed/
MATCHED REGEX REGISTERS
  regex[0] = 6-11 'world'
PATTERN: hello sed
END-OF-CYCLE:
hello sed
```

逐段读：

- `SED PROGRAM` 是 sed 解析后的脚本。
- `INPUT` 说明当前读的是哪个输入、第几条记录。
- `PATTERN` 是执行命令前的模式空间。
- `COMMAND` 是当前尝试执行的命令；地址不匹配时也会显示，但不会真正执行。
- `MATCHED REGEX REGISTERS` 给出正则命中的位置和文本。
- 第二个 `PATTERN` 是替换后的模式空间。
- `END-OF-CYCLE` 之后是默认打印的结果。

`--debug` 的输出格式可能随版本变化。本教程的记录来自 GNU sed 4.9；如果你的版本格式略有不同，按这些关键字段理解即可。

### 常见误解

| 误解 | 实际行为 | 怎么验证 |
| --- | --- | --- |
| sed 会直接修改文件 | 默认只写标准输出；要改文件必须用 `-i` 或重定向 | 运行后看原文件，内容不变 |
| `s` 会替换整行所有匹配 | 默认只替换每行的第一个匹配；全部替换要加 `g` | 用 `a a a` 测试 `s/a/X/` 与 `s/a/X/g` |
| 模式空间包含行尾换行 | 不包含；换行是记录分隔符，默认打印时再补 | 用 `od` 查看输出字节，确认没有 `0a` |
| `-n` 让 sed 不处理输入 | 只是关闭自动打印，命令仍然执行 | `sed -n 's/a/A/p'` 仍能输出替换结果 |
| `p` 只打印匹配的片段 | 打印整个模式空间 | `sed -n '/blue/p'` 输出整行 |
| 保持空间和模式空间一样 | 保持空间跨轮保留、初始为空、不自动打印 | 用 `G` 观察每行后面追加的空行 |
| sed 一次读入整个文件 | 默认逐行读；只有 `N`、`-z` 等会改变记录范围 | `--debug` 的 `INPUT ... line` 逐条递增 |

### 练习

- 对 `printf 'a\nb\nc\n'` 运行 `sed -n '2p'`，预测输出后再执行。
- 对同一输入运行 `sed '2d'`，解释为什么第 2 行没有留下空行。
- 下面两条命令的输出分别是什么？先预测再运行。

```shell
printf 'a a\n' | sed 's/a/A/'
printf 'a a\n' | sed 's/a/A/g'
```

- 用 `sed --debug` 观察 `sed -n '1p' examples/data/poem.txt`。为什么 `COMMAND` 出现了多次，但只有一次输出？
- 用 `G` 处理 `examples/data/poem.txt`，解释最后为什么多出一个空行。

<details>
<summary>参考答案</summary>

第一条只替换第一个 `a`，输出 `A a`；第二条替换全部，输出 `A A`。

`sed --debug` 会为每条输入记录显示 `COMMAND: 1 p`，但地址 `1` 只匹配第 1 行，所以只有第 1 行真正执行 `p`。其余记录到达 `END-OF-CYCLE` 时，`-n` 关闭了自动打印，因此没有输出。

`G` 把“换行加保持空间”追加到模式空间。保持空间为空，模式空间末尾多了一个换行；默认打印又补一个换行，于是每行后面出现一个空行。最后一行也会追加，所以文件末尾同样多一个空行。

</details>
