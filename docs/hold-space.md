## 保持空间与流程控制

到目前为止，所有命令都只处理当前模式空间。模式空间在每轮结束时被清空，下一行重新开始，所以 sed 默认“记不住”上一行。

**保持空间**(hold space)是 sed 提供的第二块缓冲区。它不会被自动清空，也不会被自动打印，可以在不同记录之间传递状态。配合标签和分支，sed 就能写出反转、去重、合并续行这类跨行脚本。

保持空间很强，但也容易把脚本写成“只有作者看得懂”的样子。能用 awk 清楚表达的逻辑，不必强行用 sed。

### 保持空间命令

| 命令 | 作用 |
| --- | --- |
| `h` | 用模式空间覆盖保持空间 |
| `H` | 把模式空间追加到保持空间，前面加一个换行 |
| `g` | 用保持空间覆盖模式空间 |
| `G` | 把保持空间追加到模式空间，前面加一个换行 |
| `x` | 交换模式空间和保持空间 |

初始时保持空间为空。模式空间是当前读入的行。`h`/`H` 把内容送进保持空间，`g`/`G` 把内容取回模式空间。

`H` 和 `G` 都会插入一个换行，即使另一侧是空的。这解释了为什么很多保持空间脚本里会出现 `s/^\n//` 这样的清理：第一次 `H` 会把一个空行拼到内容前面。

### 每行后面加空行

最简单的保持空间例子是给每行后面加一个空行：

```shell
sed 'G' examples/data/poem.txt
```

输出：

```shell
roses are red

violets are blue

sed is a stream editor

and so are you

```

`G` 把“换行加保持空间”追加到模式空间末尾。保持空间是空的，所以模式空间末尾多了一个换行；默认打印再补一个换行，于是每行后面出现一个空行。

这个例子还没有真正跨行保存状态，只是用了 `G` 的追加行为。下面看一个真正需要保持空间的脚本。

### 反转文件

```shell
sed -n '1!G;h;$p' examples/data/poem.txt
```

输出：

```shell
and so are you
sed is a stream editor
violets are blue
roses are red
```

脚本很短，但每一步都依赖保持空间：

- `1!G`：除第 1 行外，把保持空间追加到当前行后面。保持空间里存的是已经处理过的行，按倒序排列。
- `h`：把当前模式空间复制回保持空间，更新倒序历史。
- `$p`：只在最后一行打印。

用三行输入 `1`、`2`、`3` 走一遍：

| 读入 | `G` 后的模式空间 | `h` 后的保持空间 | 输出 |
| --- | --- | --- | --- |
| `1` | `1` | `1` | 无 |
| `2` | `2<br>1` | `2<br>1` | 无 |
| `3` | `3<br>2<br>1` | `3<br>2<br>1` | `3<br>2<br>1` |

第 1 行跳过 `G`，因为 `1!` 否定了第 1 行；`h` 把 `1` 存进保持空间。第 2 行 `G` 追加保持空间，得到 `2` 换行 `1`；`h` 再把它存回保持空间。第 3 行同理，最后 `$p` 打印整个倒序结果。

`-n` 关闭了自动打印，否则每一轮的中间结果都会被输出。这是保持空间脚本的常见结构：**用 `-n` 控制输出，只在正确的时机 `p`**。

### 删除非相邻重复行

相邻重复行可以用 `N` 和比较轻松处理。非相邻重复需要记住所有已经见过的行，正好适合保持空间：

```shell
sed -n 'G;/^\(.*\)\n\(.*\n\)*\1$/d;P;H' examples/data/employees.txt
```

输出：

```shell
alice
bob
carol
dave
```

逐段解释：

- `G` 把当前行和保持空间拼起来，模式空间变成“当前行 + 换行 + 历史”。
- `/^\(.*\)\n\(.*\n\)*\1$/` 捕获当前行，检查历史里是否已经出现过同一行。
- `d` 在重复时删除整个模式空间，开始下一轮。
- `P` 只打印模式空间的第一行，也就是当前行，不打印历史。
- `H` 把当前行追加到历史，供后续行比较。
- `-n` 阻止默认打印，否则每一轮的“当前行 + 历史”都会被输出。

这个脚本有两个重要限制：

- 它用正则比较，不是按字面量比较。当前行如果包含 `.`、`*`、`[` 等正则元字符，可能误判。
- 它把所有出现过的行都保存在内存里。文件很大时，内存占用会持续增长。

生产环境里，按字面量去重并保持顺序，用 awk 更稳：

```shell
awk '!seen[$0]++' examples/data/employees.txt
```

输出相同。需要排序去重时，用 `sort -u`；需要保留首次出现顺序时，awk 是更合适的选择。

### 合并反斜杠续行

配置文件里常见用反斜杠续行：

```ini
DATABASE_URL=postgres://db:5432/app \
  ?sslmode=require
CACHE_URL=redis://cache:6379/0
```

下面的脚本把续行合并成一行，并去掉反斜杠和下一行开头的缩进：

```shell
sed -e :a \
    -e '/\\$/N' \
    -e 's/[[:space:]]*\\\n[[:space:]]*/ /' \
    -e 'ta' \
    examples/data/continuation.conf
```

输出：

```shell
DATABASE_URL=postgres://db:5432/app ?sslmode=require
CACHE_URL=redis://cache:6379/0
```

逐段解释：

- `:a` 定义标签 `a`。
- `/\\$/N` 如果当前模式空间以反斜杠结尾，用 `N` 读入下一行。正则 `\\$` 里的 `\\` 匹配一个字面反斜杠，`$` 匹配行尾。
- `s/[[:space:]]*\\\n[[:space:]]*/ /` 把“可选空白 + 反斜杠 + 换行 + 可选空白”替换成一个空格。
- `ta` 如果刚才的替换成功，跳回标签 `a`，继续检查新行是否也以反斜杠结尾。

如果续行有三行，`ta` 会循环两次；如果下一行不再以反斜杠结尾，`/\\$/N` 不成立，脚本自然结束。

反斜杠在 shell 单引号和 sed 正则里都是转义字符，写这类脚本时先用小样本测试。多一层或少一层反斜杠，行为就会完全不同。

### 标签与分支

sed 的流程控制靠标签和分支命令：

| 写法 | 作用 |
| --- | --- |
| `:name` | 定义标签 `name` |
| `b name` | 无条件跳到标签 `name` |
| `b` | 无条件跳到脚本末尾，继续默认输出 |
| `t name` | 自上次读入新行或执行 `t` 以来，如果有 `s` 成功，跳到 `name` |
| `t` | 同上，跳到脚本末尾 |
| `T name` | 自上次读入新行或条件分支以来，如果没有 `s` 成功，跳到 `name`；**GNU** |
| `T` | 同上，跳到脚本末尾；**GNU** |

标签定义本身不产生输出。`b` 跳到脚本末尾后，当前模式空间仍然会在本轮结束时被默认打印（除非 `-n`）。

一个常见的“跳过处理”写法：

```shell
sed '/^#/b;/^$/b;s/^/  /' examples/data/hosts.txt
```

注释行和空行直接跳到末尾，不执行缩进；其余行加上两个空格。输出里注释保持原样，主机记录被缩进。

`t` 适合写循环。下面把连续多个空格压成一个：

```shell
printf 'a  b   c    d\n' | sed ':a;s/  / /;ta'
```

输出：

```shell
a b c d
```

`s/  / /` 每次只替换第一处双空格；`t` 在替换成功后跳回 `:a`，继续找下一处，直到没有双空格为止。

`T` 是 `t` 的反向分支。下面的例子只给发生过替换的行加后缀：

```shell
printf 'a\nb\n' | sed 's/a/A/;T; s/$/ (changed)/'
```

输出：

```shell
A (changed)
b
```

第 1 行 `s/a/A/` 成功，`T` 不跳转，继续执行 `s/$/ (changed)/`；第 2 行没有替换，`T` 直接跳到末尾，不加后缀。

`t` 的“自上次读入新行以来”这个条件很重要。它不是一个全局的“曾经替换过”标志：每读入一条新记录，条件会重置；执行一次 `t` 后也会重置。写循环时不要假设它会一直为真。

### 交换相邻行

`N` 加保持空间可以交换成对的行：

```shell
printf '1\n2\n3\n4\n' | sed -n 'N;s/^\(.*\)\n\(.*\)$/\2\n\1/p'
```

输出：

```shell
2
1
4
3
```

`N` 把下一行拼进来，正则捕获两行，替换时先输出第二行再输出第一行。这个脚本一次处理两行；输入行数为奇数时，最后一行不会被 `N` 读到，也就不会输出。需要处理奇数行时，用 `$!N` 保护，或单独处理最后一行；不要简单追加 `$p`，否则偶数行数时最后一行可能被打印两次。

### 保持空间的代价

保持空间不是免费的：

- `H`/`G` 会在每次操作时复制缓冲区；在大文件上频繁使用会变慢。
- 去重、反转这类脚本会把历史保存在内存里，输入越大，占用越高。
- 正则比较可能误判含元字符的行。
- 脚本的可读性会下降，调试成本上升。

遇到“需要跨行状态”的任务，先问自己：awk 的数组、Perl 的哈希、Python 的字典是不是更直接？sed 的优势是短小和管道友好，不是复杂状态管理。
